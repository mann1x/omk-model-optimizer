# gemma-4-20B-v9-agentic-base-mlk8-noa-sft11 — GGUF (K-FAC quantizations)

GGUF quantizations of
[ManniX-ITA/gemma-4-20B-v9-agentic-base-mlk8-noa-sft11](https://huggingface.co/ManniX-ITA/gemma-4-20B-v9-agentic-base-mlk8-noa-sft11):
[google/gemma-4-26B-A4B-it](https://huggingface.co/google/gemma-4-26B-A4B-it) pruned to **98 of its 128 experts per
layer** with the v9-agentic `ml_k8` competence map (no shared-expert upweight), then given **one pass of the sft11
recipe** — the on-policy, loop-free agentic recovery SFT of
[gemma-4-26B-A4B-agentic](https://huggingface.co/ManniX-ITA/gemma-4-26B-A4B-agentic) — on the pruned weights.
30 layers × 98 experts, 20.45 B parameters (19.9 B in the GGUF, which carries no vision tower), ~4 B active per token
(top-8 + shared). Same tokenizer, chat template, attention and norms as Gemma 4 26B-A4B-it.

**Every tier here is K-FAC rounded**, not a plain `llama-quantize` output: same file format, same layout, same size as
the stock tier, but the MLP weights are re-rounded against the model's own curvature. On this model that removes
7–42 % of the quantization error at identical size from Q6_K down (1 % at Q8_0, where little is left to remove),
measured below tier by tier. The finest tier is IQ2_XS; there is no trained 2-bit (QAD) tier in this repo.

## The model

- **Prune.** Expert drop by contribution with the v9-agentic `ml_k8` map: 30 of the 128 routed experts removed in every
  layer (900 in all), the router rows sliced to match, **no rescaling of the shared (dense) FFN**. Tokenizer, chat
  template, attention, norms, embeddings and vision tower are the vendor model's, untouched.
- **SFT — the sft11 recipe, once.** The corpus of gemma-4-26B-A4B-agentic: prompts, tools and recorded tool outputs
  from nine NVIDIA Nemotron SFT sets and interstellarninja/hermes_reasoning_tool_use, every trained assistant turn
  regenerated by the untouched Gemma-4-26B-A4B-it in its own chat template (thinking on) and kept only when a validator
  found no loop, no foreign token and a tool call equivalent to the recorded one; one source regenerated by
  Gemma-4-31B-it (Kimi-K2.5 agent tasks). 16,296 conversations → 4,217 windows of 16,384 tokens, one epoch.
  Published: [ManniX-ITA/gemma-4-26B-A4B-agentic-sft](https://huggingface.co/datasets/ManniX-ITA/gemma-4-26B-A4B-agentic-sft),
  [ManniX-ITA/hermes-agent-kimi-traces-gemma4-31b](https://huggingface.co/datasets/ManniX-ITA/hermes-agent-kimi-traces-gemma4-31b).
- **Training.** Attention, dense MLP, router and routed experts in bf16 (295 tensors, 19.1 B parameters; embeddings
  and MTP head frozen), cross-entropy on the regenerated assistant tokens only, 2,108 steps × 2 × 16,384 tokens, peak
  LR 4.74e-6 with 10 warm-up steps, one RTX PRO 6000 Blackwell, 24.2 h. Held-out NLL over the eleven training
  families (token-weighted): 0.489 for the pruned, untrained model → 0.389 after the SFT.

Built with [omk-model-optimizer](https://github.com/mann1x/omk-model-optimizer) in its **BF16 recovery** mode
([guide](https://github.com/mann1x/omk-model-optimizer/blob/omk-main/omk/docs/bf16-recovery.md)); the prune with
[omnimergekit](https://github.com/mann1x/omnimergekit). Training record:
[`omk/models/gemma-4-20b-v9-agentic/train/logs/`](https://github.com/mann1x/omk-model-optimizer/tree/omk-main/omk/models/gemma-4-20b-v9-agentic/train/logs).

## How the quants are made

Toolchain: [omk-model-optimizer](https://github.com/mann1x/omk-model-optimizer)
([`docs/kfac-rounding.md`](https://github.com/mann1x/omk-model-optimizer/blob/omk-main/omk/docs/kfac-rounding.md),
[model folder with every script as run](https://github.com/mann1x/omk-model-optimizer/tree/omk-main/omk/models/gemma-4-20b-v9-agentic))
and [omnimergekit](https://github.com/mann1x/omnimergekit) `scripts/quantize_gguf.py`; llama.cpp **b12386** for every
step.

1. **F16** — `gemma-4-20B-v9-agentic-base-mlk8-noa-sft11-F16.gguf`, converted from the bf16 safetensors (658 tensors,
   `eos = 106` `<turn|>`, the official Gemma 4 chat template embedded, 18,683 B, sha256 `ae53464b…`). Text model only:
   no MTP head, no vision tower.
2. **imatrix** — [`imatrix.dat`](./imatrix.dat) (sha256 `52b65c66…`, 88.5 MB, GGUF-format imatrix under the `.dat`
   name): the [AtomicChat](https://huggingface.co/AtomicChat) calib-corpora recipe `gemma-4-20b-v9-agentic`
   **rendered through the Gemma 4 chat template** (real `<|turn>` / `<|channel>` / `<|tool_call>` structure),
   **all 9,590 chunks of 512 tokens (4.91 M tokens), `--parse-special`**, computed on this F16. 295 entries; every
   tier carries its `quantize.imatrix.*` keys.
3. **stock tier** — `llama-quantize --imatrix imatrix.dat` at the tier, with the **Gemma-4 A4B attention rule**: the
   attention projections (`attn_q/k/v/output`) are **Q8_0 from Q4_K_M upward and Q6_K below** (they are small and the
   MoE is sensitive to them). This file is the reference: what llama.cpp alone produces, scored in the table as
   *llama-quantize + imatrix*. It is not published.
4. **K-FAC rounding** — `omk_qad.kfac_round --stems all --qtype auto --ref <stock tier>`: every MLP tensor (routed
   experts' gate_up and down, dense gate/up/down) is re-rounded by GPTQ at the encoder's own 256-column block, with
   the real llama.cpp encoders (byte-identical codes) and the layer's Kronecker-factored curvature `H ≈ G ⊗ A`
   (`A` = input second moment, `G` = sampled-label Fisher of the output, diagonal for the expert down-projections),
   collected on 512 windows × 2,048 tokens of the model's own agentic corpus with the attention-sink positions
   excluded. Output = a byte copy of the stock file with the MLP payloads replaced, so the two differ only by the
   rounding: same tensor types, same byte count, same metadata (imatrix keys included).
5. **twin score** — both files are scored against this model's own F16 (llama.cpp kernels on both sides) on 44
   held-out agentic windows, 256,853 assistant positions: mean top-256 KL(F16 ‖ quant) and top-1 agreement. The K-FAC
   file is published only when it beats its stock twin.

## Files

<!-- OMK:TIERS -->

**Reading the table.** `KL` = mean KL divergence of the quant's next-token distribution from the F16's over the
F16's top 256 tokens, on the held-out assistant positions (lower is better; 0 = identical); `top-1` = share of
positions where both pick the same token. `ΔKL` = the K-FAC file's KL relative to its stock twin at identical size.
`bpw` = 8 × bytes ÷ the GGUF's tensor element count. sha256 is the file's; the full value is in each `.gguf.sha256`.

**Other files.** `gemma-4-20B-v9-agentic-base-mlk8-noa-sft11-F16.gguf` — the unquantised conversion the ladder starts
from (39.79 GB, sha256 `8f984405…`). `imatrix.dat` — the importance matrix above, for audit and reproduction.
There is no vision projector in this repo: neither the prune nor the SFT touches the vision tower, so the Gemma 4
26B-A4B-it projector is the matching one; vision was not tested on this build.

## How to use

```bash
llama-server -m gemma-4-20B-v9-agentic-base-mlk8-noa-sft11-Q4_K_M.gguf -c 32768 -ngl 99 --jinja -fa on \
    --chat-template-kwargs '{"enable_thinking": true}' \
    --reasoning-budget 8192 \
    --reasoning-budget-message $'\n\nI have used my thinking budget. I must stop analysing now and act on what I have: make the tool call, or give a short final answer if no call is needed.\nI\'ll be more terse and concise now and maybe I need to consider a different approach.\n'
```

- **`--jinja` is required**: it uses the embedded official template and gives the reasoning budget its delimiters.
- **Sampler.** The GGUF carries the vendor defaults (temperature 1.0, top_k 64, top_p 0.95). The sampler the
  26B agentic parent is deployed with — temperature 0.8, top_p 0.95, top_k 64, **min_p 0** (llama.cpp defaults to
  0.05), presence_penalty 0.035, no repetition penalty — is the starting point for this build; its validation on this
  model is pending and the recommendation will be recorded here when the evaluation is done.
- **`--reasoning-budget`** bounds the thinking block (keep `-c` several times larger); the stop phrase tells the model
  to act on what it has. Per-request overrides: `thinking_budget_tokens`, `reasoning_budget_message`
  (llama.cpp ≥ b10091).
- End of turn is token **106** (`<turn|>`), in the GGUF metadata.
- Speculative decoding: the Gemma 4 assistant drafter
  ([`gemma-4-26B-A4B-it-assistant-GGUF`](https://huggingface.co/ManniX-ITA/gemma-4-26B-A4B-it-assistant-GGUF) Q8_0)
  has the vocabulary and hidden size of this model and runs with it on engines with Gemma-4 draft-assistant support;
  the acceptance rate was not measured on this build.
