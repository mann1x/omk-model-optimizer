# Qwen3.5-4B — M6

First model trained end to end with `omk_qad`: two students over one shared teacher, an **IQ2_XXS** student and a
**ternary (PQ2_0)** student, distilled from [`Qwen/Qwen3.5-4B`](https://huggingface.co/Qwen/Qwen3.5-4B) on a ~20M-token
code-heavy mix, then exported straight to GGUF. Run name `m6_qwen35_4b`, October 2026.

| | |
|---|---|
| teacher / student base | `Qwen/Qwen3.5-4B` (hybrid: 24 Gated DeltaNet + 8 attention layers, dense MLP, tied embedding, MTP head) |
| hardware | one NVIDIA RTX PRO 6000 Blackwell (96 GB); both students trained concurrently on it |
| recipe | [`recipe_m6.yaml`](recipe_m6.yaml) (`python -m omk_qad.multi --spec recipe_m6.yaml all`) |
| corpus | [corpus catalogue](#corpus-catalogue) below; manifests in [`corpus/`](corpus/) |
| results | [`evals/results.md`](evals/results.md) / [`evals/results.json`](evals/results.json), regenerated by [`evals/collect_results.py`](evals/collect_results.py) |

## Recipe

Both students share the layout probe, the teacher top-64 cache (19,500 × 1,024-token sequences), the eval rows and
the imatrix pass. Each trains in its own process.

| student | layout | loss | lr (peak) | steps × batch | other |
|---|---|---|---|---|---|
| `iq2` | dense MLP **fixed IQ2_XXS**; everything else by llama.cpp's IQ2_M rules (attention IQ2_S/Q4_K/IQ3_S, linear attention IQ2_S/Q4_K, small projections IQ2_S, tied head Q5_K, MTP Q4_K) | Jaccard (top-K + rest) | 1e-5, warmup 50 | 2400 × 8 (19.7M tokens, one pass) | IQ2 and K/IQ3 encodings refreshed every 4 steps |
| `tern` | dense MLP, attention, linear attention and tied head **PQ2_0** (ternary, Hadamard block 512); small projections IQ2_S; MTP Q4_K | log-space top-K KL | 6e-5, warmup 200 | 2400 × 8 | `top:86` ternarizer, divergence guard 3× EMA / 3 steps |

What trains: **every quantized tensor** (257 here: 4.325B weights) is a latent fake-quantized at its own planned
type, fixed or rest, plus the ~1M float parameters (norms, biases). The MTP head is distilled with the trunk
detached (weight 0.3). "Fixed" in the layout only means the type is set by hand.

Training result (on the shared eval rows, 8 families; `klk` = top-64 KL, lower is better):

| student | init klk | final klk | top-1 | ppl | wall time | peak mem |
|---|---|---|---|---|---|---|
| iq2 | 1.166 | **0.484** | 84.9 % | 3.70 | 8.6 h | 24.3 GiB |
| tern | 8.029 | **0.463** | 79.0 % | 4.00 | 6.0 h | 29.7 GiB |

Per-family numbers: [`evals/report.md`](evals/report.md).

template, capped at 4,096 tokens per document; eval rows are drawn first and are disjoint from train

output). Eval sets: corpus_v1 `eval_code`, `eval_tech`, `eval_general`, `agent_eval` and the four mix_v1
`*.eval.jsonl`, 16 rows each.

"—" = not measured yet: the packaging ladder (student IQ2_XXS core with up-precision packaging, plus the stock 3/4-bit
intermediates) was still running when this page was written.

What the measured rows show:

- **The IQ2_XXS student beats every stock 2-bit quant on code**: 38.4 / 31.7 (HE / HE+) at 1.66 GB against stock
  IQ2_XXS 10.4 / 9.8 (1.61 GB) and stock IQ2_S 23.2 / 18.9 (1.72 GB).
- **The trained grid matters**: the same weights with the MLP re-encoded at IQ2_XS have *better* KLD (0.324 vs 0.350)
  and score 10 points *lower* on HumanEval. The MLP was trained for IQ2_XXS's codebook, and the IQ2 grids are not
  nested. Wiki KLD does not rank coding ability between these files.
- **The ternary student at 1.20 GB beats stock IQ2_XXS** (17.7 vs 10.4 HE) at three quarters of its size. PQ2_0 runs
  only on PrismML's llama.cpp fork and opencoti's engine; the engine control (Q4_K_M on both) moves HE by 2.4 points.
- Q4_K_M scoring above F16 (62.8 vs 57.9) is inside the run-to-run noise (± ~3.8 points at n = 164).

Sample sanity (every run): no empty generations, no code fences, no leaked thinking. Two flags are real model
behaviour, not scoring faults: the student re-encoded at IQ1_M answers 11 problems with a bare `pass`, and stock
IQ2_XXS falls into repetition loops.

Reference, different pipeline and basis (not comparable cell for cell): the earlier ternary QAT of this base
(`bonsai4b_qat`, r1, vLLM bf16) scored HE 10.37 % (mix) / 0.61 % (FineWeb only) against a 59.76 % base.

## Reproduce

```bash
python -m omk_qad.multi --spec omk/models/qwen3.5-4b/recipe_m6.yaml all    # plan, cache, preflight, train, export, report
bash omk/models/qwen3.5-4b/evals/scripts/m6_compare.sh                      # stock Q4_K_M / IQ2_S + KLD
bash omk/models/qwen3.5-4b/evals/scripts/m6_he.sh                           # opencoti KLD control + HumanEval
bash omk/models/qwen3.5-4b/evals/scripts/m6_xquants.sh                      # IQ grid exports + stock IQ1_M/IQ2_XS/IQ2_XXS + HE+
bash omk/models/qwen3.5-4b/evals/scripts/m6_pack.sh                         # packaging ladder + stock 3/4-bit
python omk/models/qwen3.5-4b/evals/collect_results.py <run dir>             # results.json + results.md
```

The spec and scripts are the files as run: paths are the training host's (`/mnt/sdc/omk-model-optimizer`).
